## 1. 已确认的决策（不再讨论）

| 编号 | 决策 | 取值 |
|---|---|---|
| D1 | 开发基线 | **方案 A**：ESPHome 外部组件；社区 `esphome-xiaomi_bslamp2` 提供灯光与触控面板 HAL |
| D2 | 方案 B 能力 | 通过**可移植纯 C99 核心库**保证（协议/设备表/状态机/灯效/夜间模式），将来可整体搬进纯 ESP-IDF |
| D3 | Python 边界 | 工程内 Python **仅限** ESPHome 组件必需的 `__init__.py`（PC 端代码生成，不进设备）；其余全部 C99 |
| D4 | 手机控制 | **档 1（内置网页）+ 档 2（MQTT / HomeAssistant Discovery）** |
| D5 | 网页功能 | 列出所有狗的状态 / 电量 / 信号，**支持为每只狗命名** |
| D6 | 设备表容量 | 编译期默认 **8**，运行期可在网页设置 **1–16**，写入 NVS |
| D7 | 多狗合并规则 | **最活跃者优先**（Active > Light > Quiet） |
| D8 | 夜间模式 | 时间窗 22:00–07:00 + 无时钟空闲推断 + App/网页开关 |
| D9 | 手动豁免 | **10 分钟可配**（1–120 分钟），任何用户操作刷新计时 |
| D10 | 手动豁免语义 | 进入"手动模式"期间**暂停自动宠物灯效**、夜间压制不生效；超时回落自动模式 |
| D11 | 原厂功能 | 物理面板 3 类交互 + 12 颗指示灯 + 彩光/白光/夜灯 **全部保留** |
| D12 | 网页安全 | **加 Basic Auth 密码**（成本几乎为零；同 WiFi 下默认任何人可控制灯） |
| D13 | 狗名默认 | **`Pet-1` / `Pet-2` …**（网页上可改成真名） |
| D14 | 夜间 Active 上限 | **18（≈ 7% 逻辑亮度）** |
| D15 | 多狗时色彩键 | **多狗时改用途**：循环"合并 / 只看狗N"；色相切换移到**长按**（单狗时行为完全不变） |
| D16 | Wi-Fi/BLE 共存 | **`PREFER_BALANCE`** 先试，按实测有效包率再调 |

```
│  │ esp32_ble_tracker   被动扫描 + 原始广播回调 │

│  │ device_registry.c   设备表 / 最活跃者优先 / 每狗统计 │
│  │ state_machine.c     失联判断 / 状态转移        │
│  │ lamp_effects.c      灯效目标值 / Gamma / 过渡 / 限流 │
│  │ night_mode.c        时间窗 / 空闲推断 / 手动豁免   │
│  └───────────────────────────────────────┘
│                            │
│  ┌── 本工程胶水（C++，只做转换）────────────┐
│  │ pet_lamp_component  订阅 BLE 广播 → 喂核心库    │
│  │ pet_lamp_output     核心库 → 驱动 bslamp2 灯    │
│  │ pet_lamp_web        网页 API / 每狗命名 / 设置    │
│  └───────────────────────────────────────┘
└────────────────────────────┘
```

**数据流**：

```
佩戴端广播
  │
  ▼ esp32_ble_tracker 原始回调（只做入队，不做解析）
环形缓冲（FreeRTOS queue，16 项）
  │
  ▼ pet_rx 任务（20 Hz）
pet_protocol 解析 + 六层校验
  │
  ▼ device_registry 更新该 DeviceID 的记录
  │    ├── last_seen / sequence / activity_state / score
  │    ├── battery / flags / rssi
  │    └── 生命周期统计
  ▼
state_machine（1 Hz）+ device_registry 合并（最活跃者优先）
  │
  ▼ night_mode 计算 brightness_cap + 是否抑制低电量提示 + Active 节流
  │
  ▼ lamp_effects（50 Hz）→ pet_lamp_output → bslamp2 light
  │
  ▼ web / MQTT 暴露状态；NVS 持久化设置与狗名
```

**任务划分**（沿用现有实现，符合需求 §6.3 频率要求）：

| 任务 | 频率 | 职责 |
|---|---|---|
| `pet_rx` | 事件驱动，20 Hz 轮询 | 取广播 → 解析 → 更新设备表 |
| `pet_state` | 1 Hz | 失联判断、合并、夜间模式、诊断汇总 |
| `pet_fx` | 50 Hz | 灯效插值 + 写灯 |
| `web/mqtt` | 框架自带 | UI 与集成 |

## 4. 六个工作包（WP）

### WP1 — 可移植核心库（`core/`）

**目的**：方案 B 的能力载体。全部纯 C99，无 ESP-IDF / ESPHome 依赖，可在 PC 上编译测试。

| 文件 | 内容 | 相对现状的改动 |
|---|---|---|
| `pet_protocol.{h,c}` | 广播解析 / CRC-8 / 字段校验 | 从 `protocol/` 移入，逻辑不变（已通过向量测试） |
| `pet_config.h` | 集中配置宏 | 从 `app_config.h` 拆出平台无关部分，新增夜间/多狗宏 |
| `device_registry.{h,c}` | **新增**：设备表 + 合并规则 + 每狗统计 | 全新 |
| `state_machine.{h,c}` | 失联判断 / 状态转移 | 从"单 DeviceID"改为遍历设备表 |
| `lamp_driver.{h,c}` | Gamma / 限流 / 层调制 | 平台无关化：PWM 写入改为函数指针回调 |
| `lamp_effects.{h,c}` | 目标值 / 过渡 / 呼吸 / 恢复动画 | 增加 `brightness_cap` 入参 + Active 节流 |
| `night_mode.{h,c}` | **新增**：时间窗 / 空闲推断 / 手动豁免 | 全新 |

### WP2 — ESPHome 外部组件（`esphome/components/pet_status_lamp/`）

#### 2.1 为什么能白拿（依赖清单）

| 依赖 | 提供的 | 我们的用法 |
|---|---|---|
| `esp32_ble_tracker` | ESP32 被动 BLE 扫描、原始广播回调、RSSI | 实现 `ESPBTDeviceListener`，`parse_device()` 里只入队 |
| `xiaomi_bslamp2`（[仓库](https://github.com/mmakaay/esphome-xiaomi_bslamp2)） | RGB/白光/主开关/触控面板 HAL/12 颗面板指示灯 | 作为输出目标 + 面板事件源 |
| `web_server` | HTTP 基座、实体页面 | 挂自定义端点与页面 |
| `mqtt` | HA Discovery | 发布状态实体 |
| `api` | HA 原生 API | 直接可用 |
| `ota` | OTA | 直接可用 |
| `time`（SNTP 或 HA 时间源） | 时钟 | 夜间时间窗判据；无时钟时退化 |

> ⚠️ **Wi-Fi 与 BLE 共存**：ESP32 单射频，二者共存会互相抢占。必须开启
> `CONFIG_SW_COEXIST_ENABLE` 并把 `CONFIG_ESP_COEX_SW_COEXIST_PREFERENCE` 设为
> `PREFER_BALANCE`，同时在 YAML 里显式配置。这会略微降低 BLE 收包率，
> 需要在 §10 的验收里按有效包率确认（需求 8.3 要求 3–5 米接近 100%）。

### WP3 — 多狗支持（设备表 + 合并 + 命名）

| 项 | 实现 |
|---|---|
| 容量 | 编译期默认 8；`pet_reg_set_cap()` 运行期 1–16，写 NVS `pet/maxdev` |
| 绑定 | 配对模式 60 秒内接受**所有**合法 `PAIR_REQUEST` 包，每加入一只白闪一次；写 NVS |
| 每狗独立计时 | `last_seen_ms` 逐设备维护；**单只超时不触发 Lost**，全部超时才 Lost |
| 合并规则 | `Active > Light > Quiet`；相同状态取 `activity_score` 更高者 |
| 焦点锁定 | `focus_index`：`0xFF`=合并显示（默认）；否则只看某只。面板**色彩键短按**循环切换，写 NVS |
| 命名 | 每狗 `name[17]` UTF-8，网页可改，写 NVS `pet/dN/name` |
| 面板指示 | 12 颗指示灯里用 1–8 颗表示"当前显示的狗序号"（复用原厂硬件，不新增元件） |
| 配额与淘汰 | 表满时拒绝新设备并在网页提示；网页可逐只解绑 |
| 多狗颜色 | **不做**按狗区分色调（会破坏"颜色=活动强度"语义）。如需，后续加开关 |

**NVS 键规划**（命名空间 `petlamp`）：

| 键 | 类型 | 说明 |
|---|---|---|
| `maxdev` | u8 | 运行期容量 1–16 |
| `focus` | u8 | 焦点索引，0xFF=合并 |
| `cnt` | u8 | 已绑定数量 |
| `d0..d15/id` | u32 | 第 n 只的 DeviceID |
| `d0..d15/nm` | str | 第 n 只的名字（≤16 字节） |
| `brlim` | u8 | 滑条全局亮度上限 |
| `lostto` | u32 | 失联超时 ms |
| `novr` | u32 | 手动豁免时长 ms |
| `nit_on` | u8 | 夜间模式开关 |
| `nit_s/e` | u8 | 夜间时间窗起止小时 |
| `nit_ci/cl/ca/cl` | u8 | 四档夜间亮度上限 |
| `nit_thr` | u32 | Active 夜间节流 ms |

### WP4 — 夜间模式 + 手动豁免

已确认参数（`pet_config.h` 默认值，全部可被 YAML 覆盖并写 NVS）：

| 参数 | 默认 | 范围 |
|---|---|---|
| 夜间模式 | 开 | 开/关 |
| 时间窗 | 22:00–07:00 | 0–23 |
| 无时钟空闲推断 | 120 分钟 | 10–600 |
| 手动豁免时长 | **10 分钟** | **1–120** |
| 夜间上限 Quiet | 10（≈4%） | 0–255 |
| 夜间上限 Light | 14（≈5.5%） | 0–255 |
| 夜间上限 Active | 18（≈7%） | 0–255 |
| 夜间上限 Lost | 6（≈2.4%） | 0–255 |
| Active 夜间节流 | 60 秒/次 | 10–600 |
| 夜间抑制低电量提示 | 是 | 是/否 |

**状态机语义**（D10）：

```
         用户操作（短按开灯 / 滑条 / 色彩键 / 网页 / MQTT）
   AUTO ──────────────────────────────────────────▶ MANUAL
     ▲                                                │
     │  无操作满 override_ms（夜间回到带压制的 AUTO）    │
     └────────────────────────────────────────────────┘

AUTO  ：渲染宠物状态；夜间乘 cap；Active 受节流；低电量提示可被抑制
MANUAL：暂停自动宠物灯效；按用户设定输出；夜间 cap 不生效
```

**"无操作"计时器刷新条件**（任一即刷新）：面板任意键、滑条、网页/MQTT 任意命令、
宠物状态发生显著变化（仅用于空闲推断，不用于豁免）。

**豁免期间的状态变化**：不切回自动（这正是"不打扰"的关键）。这一点如果后续觉得太静，
可增加一个配置项 `MANUAL_KEEP_AUTO_HINT`（豁免期间仍用极暗色温偏移提示状态变化），
默认关闭。
